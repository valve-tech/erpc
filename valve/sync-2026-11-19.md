# Upstream sync, 2026-11-19

This merge brings erpc/erpc main `b577c289` into the fork. The last sync was
`f6e4663c` (2026-11-04). Upstream had 65 new commits, and the fork had 156.

## The 0.3.0.19 line

Production runs `0.3.0.19-valve`, tagged on `fix/fallback-order-pin-bootstrap`
(tip `2530265a`), 7 commits past the fork main this sync started from. A second
merge brings that line in, so no release from this branch drops it: the
failover pin and fallback-escape fixes, init probes that spend no rate-limit
budget, and the configured chainId when `eth_chainId` is not served. Two ports
were needed: `withPinnedFallbacks` now runs inside upstream's `selectionOrder`,
and its internal-request check reads `UpstreamPolicies() !=
UpstreamPoliciesConfigured`, because #1335 deleted `RequestDirectives.IsInternal`.

## Why it was hard

One upstream commit, #1335 "one chain tracker per network" (`528d990c`),
touched 68 of the 69 conflicted files. It replaced per-upstream head tracking,
the push indexer and the WebSocket subscription model. Many fork patches sat on
code it deleted. [conflict-minimization.md](conflict-minimization.md) measures
this and ranks the ways to make the next sync cheaper.

## Fork behaviour kept on upstream's structure

- X-ERPC-Served, upstream URL redaction, requestFormat, forwardBlockNumber,
  non-eth (passthrough) subscriptions, cacheKeySuffix, mirror policy.
- F7, empty-authoritative final. Routing only reorders upstreams, and
  upstream's refusal rule covers only blocks above Firm, so F7 is still needed.
  Its tests now model #1335's head votes.
- cf55c731, the cold-block-time order guard, with a forked-below partition
  added so it does not undo #1487.
- Poller fixes for bug log 20, 22, 23, 62 and 66, re-applied to upstream's
  new poller. `PollLatestBlockNumberAtLeast` is now a thin wrapper on
  `AskReaching`.
- The fork default that keeps "latest"/"finalized" for eth_call,
  eth_getBalance, eth_getTransactionCount and eth_estimateGas (87db2e45).
  Several adapted tests assume it.

## Fixed in this merge

- #1458's batch cap ran before authentication and called `GetNetwork` for each
  `networkId` in the body. That built a network, probed every provider and
  cached a client for any chain id an unauthenticated caller named. The cap now
  reads its limit from config only (`erpc/http_batch_cap_config.go`). Test:
  `TestClientBatchCap_DoesNotBuildNetworksBeforeAuth`, which fails on the old
  code.
- The dead WS budget and queue metrics are deleted from `telemetry/metrics.go`.
